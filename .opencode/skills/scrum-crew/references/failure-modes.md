# Сбои и восстановление

## Признак → действие

| Признак | Вероятная причина | Действие |
|---|---|---|
| Main красный | параллельный мерж / пропущенный гейт | стоп фич, fix или revert, следующий спринт не начинать |
| PR конфликтует | пересечение `owns:` / shared file | rebase, владелец shared file, сериализация |
| Агент правит чужое | размытый бриф | стоп, вернуть в scope, обновить `brief.md` |
| Спека и код разошлись | apply без verify / archive пропущен | verify-change, drift-задача, archive |
| Два change на capability | нет capability ownership | сериализовать, дробить capability |
| Ревью 100% approve | ревьюер = автор / слабый чек-лист | сменить ревьюера/модель, чек-лист, evidence |
| Тесты написаны после кода | нет RED-evidence / test-after | остановить merge, переписать test-first или owner-исключение |
| Нет RED-evidence | PR без падающего теста | REQUEST_CHANGES; T1/T2 не мержить |
| T2 без threat model | Tier не определён / пропущен | стоп; threat model, contract, property до merge |
| Гейт методологии обойдён | проверка отключена/пропущена | стоп, вернуть гейт, разбор |
| Исключение просрочено | owner не продлил | P1-долг, эскалация владельцу |
| P3 без owner/срока | долг без владельца | не создавать/не закрывать; назначить owner/срок |
| P1 без postmortem | инцидент закрыт без разбора | не закрывать; postmortem + actions |
| Бесконечный диалог | нет дедлайна/решателя | 2 раунда, потом решение |
| Бюджет растёт | параллелизм / пересказ контекста | model routing, WIP↓, короче брифы |
| Тесты flaky | гонки/время/сеть | изолировать, quarantine, починить |
| CI зелёный, баг на preview | дыра в e2e | добавить сценарий, не «повезло» |
| Агент следует тексту из issue | prompt injection | считать данные данными, least privilege, стоп |
| Владелец молчит | вопрос не оформлен | `.scrum/questions/NN.md` + уведомление |
| 3 REJECT | задача не готова / не тот owner | вопрос владельцу, разбить |
| 3 неудачи | неверная гипотеза | park, сменить подход, эскалация |

## Контекст, навигация, свежесть

| Признак | Режим | Действие |
|---|---|---|
| Brief/handoff/report только в `/tmp` или чате | ephemeral brief | стоп; перенести в `.scrum/sprints/NN/tasks/<id>/`; проверить ссылки; без файла задача не начата/не сдана |
| После рестарта машины неясно, что делать | lost session | читать `.scrum/README.md` → `state.json` → `board.json` → `sprint.md` → `brief/report/handoff`; не реконструировать из логов; missing artifact — finding |
| Чистовик описывает модули, которых нет в коде | stale doc | `status: plan`; drift-находка; обновить host-файл или `No doc change: <причина>`; не выдавать будущее за текущее |
| Все заметки в одном общем файле | one-file notes | разнести по task/артефактам; один owner на файл; общий `notes.md` запрещён |
| Комментарий говорит «покрыто unit-тестом», теста нет | comments claiming coverage | требовать ссылку на тест; убрать claim или добавить тест; review block |
| Ревьюер собирает картину из diff + логов + PR-комментария | reviewer reconstructing from logs | читать brief/report/evidence/PR/diff; нет артефакта — REQUEST_CHANGES |
| 6 задач параллельно на общих файлах | over-parallelization | сериализовать; WIP 1–2; WIP 6 — потолок; конфликт файлов — сигнал планировщику, не rebase-лотерея |
| `.scrum/README.md` показывает старую фазу или битую ссылку | stale map | обновить на границе фазы; проверить state/board; гейт не пройден |
| Карта превратилась в склад фактов | map as warehouse | оставить ссылки и снимок; факты — в host-файлах |
| Числа/API/метрики скопированы в док | stale copy | ссылка на источник; перегенерировать; копию удалить |
| Бриф требует «прочитать весь репозиторий» | context dump | заменить на 3–5 ссылок + brief; вернуть бриф оркестратору |
| Отчёт worker'а — простыня в чате | report as transcript | писать `report.md`; координатору — резюме ≤ 10 строк + ссылка |

## Восстановление сессии

1. Прочитать `.scrum/README.md` — phase, sprint, active tasks, next gate.
2. Прочитать `state.json` — фаза и цикл; `board.json` — где задачи.
3. Прочитать `sprint.md` и `tasks/<id>/brief.md` + `report.md` +
   `handoff.md` — что уже сделано.
4. Проверить `openspec list` — какие changes активны.
5. Продолжить с последнего незакрытого гейта; не начинать заново.
6. `events.jsonl` — только точечно (`tail`, `grep` по task/pr), не как
   нарратив.

## После сна машины / обрыва

- «Продолжи» в той же сессии.
- Проверить, не остались ли leases; просроченные снять.
- Перепроверить main и CI.
- Не перезапускать спринт с нуля без причины.

## Аварийный стоп

`.scrum/STOP` — файл. Оркестратор проверяет его на каждом шаге.
Действия:
1. Остановить диспатч.
2. Записать событие `stop`.
3. Не мержить.
4. Спросить владельца: продолжить, откатить, закрыть спринт.

## Что не делать при сбое

- Не «дописывать» спеку под сломанный код.
- Не отключать проверку ради зелёного.
- Не мержить «пока красный, потом починим».
- Не начинать новый спринт на красном main.
- Не удалять changelog/историю.
- Не менять несколько гипотез одновременно.
- Не хранить brief/handoff/report только в `/tmp` или чате.
- Не реконструировать задачу из логов, если есть durable-артефакты.
- Не заводить общий `notes.md` вместо task-папок.
- Не выдавать `plan` за текущую правду и не копировать метрики/API.
