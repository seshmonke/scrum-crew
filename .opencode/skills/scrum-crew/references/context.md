# Контекст и навигация

Агент носит карту, а не всю территорию. Контекст собирается
just-in-time: сначала точка входа, потом 3–5 ссылок под задачу. «Прочитай
весь репозиторий» — не бриф, а способ потерять контекст.

## Два уровня навигации + brief

```
AGENTS.md                                  проект: правила, команды, инварианты
.scrum/README.md                           спринт: phase, sprint, goal, gate, tasks
.scrum/sprints/NN/tasks/<id>/brief.md      задача: objective, AC, owns, evidence
```

Навигация — проект и спринт; задача — контекстный пакет, а не ещё один
лабиринт.

- **Проект.** `AGENTS.md` (или `CLAUDE.md`) — стабильные правила, команды,
  границы. Не пересказывает спринт.
- **Спринт.** `.scrum/README.md` — карта: где я, какой спринт и фаза,
  следующий гейт, активные задачи, 5–6 ссылок «начни здесь». Пишет только
  SM/оркестратор на границах фаз.
- **Задача.** `brief.md` — контекстный пакет. Субагент стартует с карты и
  брифа, а не с корня репозитория.

Вложенные entry-файлы (`apps/web/AGENTS.md`, `packages/contracts/AGENTS.md`)
допустимы только для подсистемы со стабильными локальными правилами. Каждый
— ≤ 1 экрана, ссылается вверх на `.scrum/README.md`, не дублирует корневой
`AGENTS.md`.

## Карта спринта

`.scrum/README.md` — не склад фактов, а роутер. В нём есть:

1. Снимок: `phase`, `sprint`, `goal`, `next gate`, `active tasks`, `WIP`.
2. «Начни здесь» — 5–6 ссылок:
   `state → board → файл спринта → brief → change → DoD`.
3. Таблица «вопрос → файл».
4. «Что не читать».
5. Контекстная шапка со `status`, `updated`, `owner`, `sprint`, `links`.

Правила:

- Пишет только SM/оркестратор; роли и worker'ы — read-only.
- Обновляется на каждой границе фаз: `INIT → PLANNING → READY → BUILDING →
  REVIEW → RETRO → CLOSED`, а также при смене активной задачи.
- Содержит ссылки и снимок, а не копии AC, контрактов, метрик и истории.
- Устаревшая фаза, несовпадение с `state.json`/`board.json` или битая
  ссылка — провал гейта. Источник истины побеждает, карта правится сразу.
- Конфликт «карта говорит A, state говорит B» не разрешается голосованием:
  читаем state/board и чиним карту.

Шаблон — `assets/context.md`; там же 5–6 ссылок и таблица «вопрос → файл».
В reference не дублируй: карта в проекте — один файл.

## Что не читать

- `events.jsonl` как нарратив — только `tail`/`grep` по событию.
- Весь репозиторий, чужие task-папки, старые спринты и `/tmp`/чат — не
  контекст; durable-путь только `.scrum/sprints/NN/tasks/<id>/`.
- Копии метрик, размеров, API и сгенерированных данных — читай источник.

## Progressive disclosure

1. **Карта** — `.scrum/README.md`, ≤ 1 экрана.
2. **Спринт** — `sprint.md`, `state.json`, `board.json`.
3. **Задача** — `brief.md`, change/proposal, контракты, DoD.
4. **Детали** — исходники, тесты, evidence, логи — только под конкретный
   AC или блокер.

Не поднимай уровень 4, пока не прочитан уровень 3. Если бриф требует
«прочитать всё» — это дефект брифа: верни его оркестратору.

## Контекстный пакет (brief)

Фиксированные поля и шаблон — `assets/brief.md`: objective, AC, owns,
контракты, non-goals, output format, tools/sources, evidence, stop
conditions, read-back. Без read-back задача не начата.

## Пример: ответ за 3 ссылки

Новый ревьюер спрашивает: «Где я, какая задача, какой спринт и фаза, где
evidence, что меняется?»

1. `.scrum/README.md` — фаза `BUILDING`, спринт `03`, задача `03.2`,
   следующий гейт `REVIEW`.
2. `.scrum/sprints/03/tasks/03.2/brief.md` — objective, AC, owns; в
   `evidence` уже указан путь `tasks/03.2/evidence/`.
3. `openspec/changes/03-checkout/proposal.md` — что меняется в поведении;
   если change не нужен — строка `No spec change: <причина>`.

Больше ничего читать не нужно: evidence лежит по ссылке из брифа, DoD — в
карте. Если ответ требует четвёртой ссылки, карта или бриф неполны.

## Свежесть

Каждый артефакт и док носят контекстную шапку:

```markdown
> **Context:** `status: active` · `updated: 2026-11-28` · `owner: SM` ·
> `sprint: 03` · `task: 03.2` · `change: checkout` ·
> links: [sprint](../sprint.md) · [board](../../board.json)
```

Статусы:

| Статус | Значение |
|---|---|
| `plan` | написано до реализации; не текущая правда |
| `active` | в работе или текущая правда |
| `done` | смержено, проверено, закрыто |
| `superseded` | заменено; ссылка на замену обязательна |

- `plan` → `active` переводит PR, который начинает реализацию; `done` —
  после merge/verify. Если doc остаётся планом — PR пишет
  `No doc change: <причина>`.
- **Host-файл** — единственное место, где факт записан; README, sprint,
  review и PR ссылаются на него. Если PR меняет факт, он правит host-файл;
  если нет — пишет `No doc change: <причина>`.
- «current» в старых текстах читается как `active`; новых значений не
  вводим.
- Дрейф: старые имена, будущее как текущее, обещание теста без ссылки на
  тест, расхождение кода и чистовика, скопированные метрики/API. Проверка —
  в ревью; см. `openspec.md`.

## Генерируемые данные

Размеры, метрики, списки API, число тестов и покрытие — из одного
источника. В доке — ссылка на источник и команду, а не копия числа. Если
число нужно в тексте, рядом дата и команда; при релизе оно перегенерируется,
а не правится вручную.

## Сбои навигации

Симптомы и действия — в `failure-modes.md`: ephemeral brief, lost session,
stale doc, one-file notes, comments claiming coverage, reviewer
reconstructing from logs, over-parallelization. Карта, которая врёт, — это
не «мелкий баг», а провал гейта.
