# Связь агентов

## Принцип

Параллельность — процессы. Совместность — шина и общие артефакты.
Свободный групповой чат запрещён: он квадратично дорог, усиливает
сикофантию и размывает ownership.

## Три уровня

| Уровень | Когда | Режим | Доля |
|---|---|---|---|
| 1. Шина + окна | обычная работа | async JSONL + sync 10–15 мин | 80–90% |
| 2. Design council | развилка, спор о контракте | дебаты 3–5 ролей, 20 мин, модератор | 5–15% |
| 3. Continuous | P0, красный main, утечка | непрерывный канал | < 5% |

Council собирается только по триггеру: 2 раунда не дали решения, цена
ошибки высока, затронуты контракт/деньги/PII/a11y.

## Топология

```
                 Оркестратор (брокер)
        ┌──────────────┼──────────────┐
        PO          Architect       Reviewers
        └──────────────┼──────────────┘
              шина + артефакты
        ┌──────────────┼──────────────┐
     Frontend       Backend        QA/Tester
     worktree 1     worktree 2     worktree 3
```

## Каналы

| Канал | Назначение | Приоритет |
|---|---|---|
| `#sprint` | Goal, изменения плана | высокий |
| `#task-N` | рабочий поток задачи | обычный |
| `#contract` | API/данные, breaking change | высокий |
| `#review-N` | ревью PR | обычный |
| `#incident` | красный main, CI, P0 | прерывает всё |
| `#design` | UX, состояния, токены | обычный |
| `#spec` | дельта поведения, spec freeze | высокий |

## Сообщение

Одна строка JSONL в `.scrum/bus/<channel>.jsonl`:

```json
{
  "id": "msg-0042",
  "ts": "2026-11-26T10:14:00Z",
  "from": "frontend",
  "to": ["backend", "architect"],
  "channel": "task-42",
  "type": "question",
  "subject": "форма ошибки checkout",
  "body": "При пустой корзине 200 или 409? Нужен контракт для UI.",
  "refs": {"task": "42", "pr": 118, "artifact": ".scrum/sprints/03/tasks/42/brief.md", "files": ["packages/contracts/..."]},
  "correlation_id": "q-0017",
  "requires_response_by": "2026-11-26T10:29:00Z",
  "confidence": "high",
  "evidence": ["curl ... -> 200"]
}
```

Правила:
- тело ≤ 1200 символов; одна тема — одно сообщение;
- вопрос обязан иметь адресата, дедлайн и `correlation_id`;
- `ack` запрещён; подтверждение — ответ по существу;
- решение ссылается на артефакт;
- старше 2 циклов — `stale`, перепроверить.

## Типы

| Тип | Ответ |
|---|---|
| `question` | да, до дедлайна |
| `answer` | нет |
| `proposal` | возражения до дедлайна |
| `objection` | да, автору |
| `decision` | нет |
| `handoff` | read-back |
| `blocker` | немедленно |
| `review` | по каждой находке |
| `status` | нет, 1 строка + ссылка на report/evidence |

## Протоколы

### Вопрос → ответ

Максимум 2 раунда. Не ответил — оркестратор назначает другого или
эскалирует. Два раунда без ответа — решает названный решатель, вопрос
становится риском.

### Предложение → возражение → решение

1. Owner публикует `proposal` с trade-off и дедлайном (10 мин).
2. Возражение — только с доказательством (тест, контракт, замер,
   стандарт).
3. Нет возражений — принято.
4. Есть — решает: PO (ценность), Architect (контракт), SM (процесс),
   DevSecOps/White Hacker (security-вето), Designer (a11y/сценарий),
   Copywriter (голос/текст).
5. Решение — в `decision` и в артефакт.

Это consent, а не consensus: не «все за», а «нет обоснованных возражений».

### Handoff

Owner пишет `.scrum/sprints/NN/tasks/<id>/handoff.md`: сделано, осталось,
грабли, проверки, открытые треды, ссылки на report/evidence. Получатель
отвечает read-back. Без read-back задача не передана. Worktree/чат — не
замена handoff-файлу.

### Отчёт

Worker пишет `report.md` в durable-папку и возвращает координатору резюме
≤ 10 строк + ссылки. Пересказ всего отчёта в чат запрещён: это дублирует
факт и раздувает контекст.

### Ревью

Находка: severity P0–P3, файл:строка, доказательство, действие. Автор
отвечает по каждой. Стиль — линтеру. Максимум 3 блокирующих на PR.

### Блокер

Прерывает focus. Оркестратор за один цикл: переназначить / изменить план
/ эскалировать. Задача не висит молча.

### Парная работа

Driver пишет и коммитит; navigator читает и пишет в `thread.md`. Право
записи в код — только у driver.

### Ревью-сворм

На один PR параллельно: QA (тестируемость), DevSecOps (authz/секреты),
Designer/a11y (доступность), Copywriter (голос/текст), White Hacker
(abuse cases). Оркестратор дедуплицирует.

### Изменение поведения

1. Автор публикует в `#spec` change + `openspec show <id> --diff`.
2. PO — зачем/скоуп, Architect — границы, QA — сценарии.
3. Возражение — со ссылкой на спеку/тест/стандарт.
4. После `decision` — spec freeze до конца apply.
5. `openspec/specs/` не правится в ветке; только archive после merge.
6. Одна capability — один активный change на волну.

## Окна цикла

| Окно | Длительность | Что можно |
|---|---|---|
| Sync | 10–15 мин | вопросы, ответы, контракты, дейлик |
| Focus | 45–60 мин | только blocker / decision / incident |

Постоянные пинги убивают работу. Совместность — в точках стыковки.

## Защита от хаоса

| Риск | Правило |
|---|---|
| Бесконечный диалог | 2 раунда, потом решатель |
| Рост токенов | ≤ 6 сообщений на задачу за цикл |
| «Все согласны» | consent + доказательство |
| Два агента в файле | lease + `owns:` |
| Рассинхрон контрактов | contract-first, `#contract`, ADR |
| Потеря сообщения | append-only + read-back + TTL |
| Статус-отчёты | `status` 1 строкой в дейли |
| Свободный чат | запрещён |

## Память ролей

Сессия роли хранит устойчивое: конвенции, решения, открытые треды.
Новая сессия стартует с `.scrum/README.md` + brief, а не с корня.
На apply — только change-папка, контракты и релевантные доки.
На archive — 5 строк в `memory/<role>.md`. Остальное — в артефакты.
