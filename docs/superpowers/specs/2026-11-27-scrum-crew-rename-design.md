# Переименование Sprint Crew → Scrum Crew

**Дата:** 2026-11-27
**Статус:** принято
**Ветка:** `task/rename-scrum-crew`

## Зачем

`scrum-crew` короче, выравнивает ID скилла с уже существующими агентами
`scrum-*` и лучше рифмуется за счёт повтора `cr`. Заодно чинится
frontmatter: сейчас `name: Sprint Crew` содержит пробел и заглавные, что
не соответствует конвенции skill-id (lowercase-hyphen).

## Что меняем

- Каталог `.opencode/skills/sprint-crew/` → `.opencode/skills/scrum-crew/`.
- Frontmatter `name: scrum-crew`; заголовок `# Scrum Crew`.
- Триггер «через scrum-crew». Старая формулировка «через sprint-crew»
  остаётся legacy-триггером на один релиз.
- Ссылки на путь и имя: агенты, `install.sh`, `install.ps1`,
  `template/AGENTS.md`, `template/docs/quality/audits/README.md`,
  `README.md`, `docs/` (DESIGN, DECISIONS, RAPTOR-SKILL, evidence).
- GitHub-репозиторий `seshmonke/sprint-crew` → `seshmonke/scrum-crew`;
  remote URL и локальный каталог `/home/frozenpunk/scrum-crew`.
- Решение фиксируется как D16 в `docs/DECISIONS.md`.

## Чего не трогаем

- Поведение и содержание методологии, шаблоны, роли, гейты.
- Версию `v0.3` и `CHANGELOG.md` — bump и release-заметки будут после
  завершения всех текущих планов по скиллу.
- Имена агентов `scrum-*`, ветки `task/quality-skill-*`, понятие
  «спринт» внутри скилла.
- Проекты-потребители, включая `localhand` и его PR #54–#56.

## Раскатка

Новая версия на проекты не ставится, пока не завершены все текущие планы
по скиллу. Переименование можно влить в `main` и открыть PR, но установка
в проекты, обновление их `.opencode/` и bump версии — отдельный финальный
шаг после закрытия текущих планов. GitHub будет редиректить старый URL
репозитория; установленные копии скилла сами не обновляются.

## Миграция

- В README добавляется раздел «Миграция с `sprint-crew`»: после
  обновления удалить старую папку `.opencode/skills/sprint-crew/`, иначе
  OpenCode увидит две версии скилла.
- Установщики не удаляют старую папку автоматически (чтобы не терять
  данные), но печатают предупреждение, если она найдена.
- Старые clone-URL и ссылки на GitHub продолжают работать через redirect.

## Ветки и PR

1. `task/rename-scrum-crew` от `main` — отдельный PR.
2. После merge три quality-ветки перебазируются на новый `main`
   (rename-detection должен перенести изменения; конфликты решаются
   вручную), затем открываются их stacked PR.
3. Раскатка на проекты — после завершения всех текущих планов.

## Проверка

- `git grep` по `sprint-crew` / `Sprint Crew`: остались только
  осознанные legacy-упоминания (триггер, README-миграция, D16,
  design/plan-документы).
- `bash -n install.sh`.
- Установка в temp-проект: появляется `.opencode/skills/scrum-crew/`,
  старой папки нет, предупреждение о старой папке срабатывает.
- Внутренние ссылки `references/` и `assets/` резолвятся.
- Frontmatter `name: scrum-crew` соответствует skill-id.
- `git diff --check`.
- `gh repo view` и `gh pr view` подтверждают новое имя и PR.

## Риски

- GitHub-redirect не покрывает некоторые API-вызовы — remote обновляем
  явно.
- В установленных проектах останется старая папка — лечится миграционной
  заметкой и предупреждением установщика.
- Переименование локального каталога ломает cwd текущей сессии — сначала
  переводим сессию в `/tmp/opencode`, затем переименовываем и
  возвращаемся в новый каталог.
- Rebase quality-веток может конфликтовать из-за смены пути — решается
  вручную после merge rename-PR.
