# Raptor-рефакторинг скилла

Отчёт по `raptor-refactor`: вопрос требований → удаление → упрощение →
ускорение → автоматизация. Замер «до / после» — в конце.

## Миссия

Скилл `sprint-crew` — переиспользуемая методология Scrum-команды агентов
для веб-разработки: Init → Sprint → Review → Retro, OpenSpec для
поведения, 12+ ролей, шина сообщений, merge train.

Главные сценарии:
1. Инициализировать новый проект: продукт → стек → delivery → walking
   skeleton.
2. Провести спринт: планирование → сборка → review → retro.
3. Переиспользовать скилл в другом репозитории.

Нельзя ломать: Scrum-правила, гейты DoR/DoD, OpenSpec-поток, безопасность,
автономность.

## Что не трогали и почему

- `roles.md` (254 строки) — это ядро инструкций, высокая тяга. Резать
  карточки в ущерб ясности нельзя.
- `communication.md` и `openspec.md` — связные единицы, не дубли.
- `orchestrator.md` — единственный источник правил 12 слотов и merge
  train.
- Скрипты состояния/мержа — преждевременная автоматизация. Сначала два
  спринта вручную, потом автоматизировать invariants.
